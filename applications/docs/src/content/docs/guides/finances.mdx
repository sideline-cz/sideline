Sideline's Finance module lets admins and members with the Treasurer role define fees (membership dues, equipment levies, tournament entry costs), assign them to members, record payments as they come in, and track team expenditures. Members can check their own balance at any time — in Discord or in the web app.

## Key concepts

- **Fee** — a named charge defined at the team level (e.g. "Spring 2026 membership", "Kit fee"). Each fee has a default amount, a currency, and an optional due date.
- **Assignment** — the record that links a fee to a specific member. An assignment inherits the fee's amount and due date, but both can be overridden per member.
- **Payment** — money received against an assignment. Payments are never deleted; they can be **voided** with a reason if recorded in error.
- **Variable symbol** — a short number (1–10 digits) attached to a member, printed on their payment QR codes and matched against incoming bank transfers. See [Setting up variable symbols](#setting-up-variable-symbols) below.
- **Bank movement** — one transaction read from the club's connected bank account. See [Connecting a bank account](#connecting-a-bank-account-fio) below.
- **Status** — computed automatically from the assignment's amounts and due date:

  | Status | Meaning |
  |---|---|
  | **Pending** | No payment received yet, due date has not passed |
  | **Partial** | Some payment received, not yet fully paid |
  | **Paid** | Fully paid |
  | **Overdue** | No or partial payment and the due date has passed |
  | **Waived** | Captain has marked this assignment as waived (e.g. hardship exemption) |

## Who can do what

Finance permissions follow a treasurer-style split across four built-in roles. By default:

| Action | Admin | Captain | Treasurer | Player |
|---|---|---|---|---|
| View fee list and assignments | Yes | Yes | Yes | No |
| View finance overview (all members) | Yes | Yes | Yes | No |
| View balance summary (Income / Expenses / Net) | Yes | Yes | Yes | No |
| Create, edit, or archive fees | Yes | No | Yes | No |
| Assign fees to members | Yes | No | Yes | No |
| Record or void payments | Yes | No | Yes | No |
| Create, edit, or delete expenses | Yes | No | Yes | No |
| View own fee status (My Payments) | Yes | Yes | Yes | Yes |
| Connect / edit the bank account (Fio) | Yes | No | Yes | No |
| View and resolve bank movements | Yes | No | Yes | No |
| Assign variable symbols to members | Yes | Yes | Yes | No |

All team members can access their own My Payments page and check their own fee balance in Discord, regardless of role.

Assigning variable symbols is the one bank-related action Captains can also do — it uses `member:edit` (which Captains hold by default) rather than a finance permission, since it is really a roster-profile field. Viewing and resolving the bank movements list itself is treasurer-only: that page shows the name, account number, and payment message of everyone who has paid the club, which is not roster-level information.

<Aside type="note" title="Planned features">
Several Finance features are planned for follow-up releases:

- **Monthly recurrence** — auto-generating monthly charges from a fee definition.
- **Self-report "I've paid"** — a Discord interaction for members to notify captains of unrecorded payments.
- **Expense receipts** — attaching an image or document URL to an expense record.
</Aside>

## Finance overview page

Go to **Team → Finances** (`/teams/:teamId/finances`) to see the full financial picture for your team. The page is visible to anyone holding `finance:view` (Admin, Captain, and Treasurer by default). The active tab is reflected in the URL so you can bookmark or share a specific view.

The page has three tabs:

**Overview tab** (default) — three KPI tiles showing team-wide totals per currency:
- **Income** — sum of all non-voided payments received
- **Expenses** — sum of all recorded expenditures
- **Net** — Income minus Expenses (may be negative)

Below the tiles, a summary table lists all active members with their total due, total paid, and assignment status counts. Use this view to quickly see who is behind on payments.

**By assignment tab** — a flat list of individual payment records. Use the filter controls to narrow by member, fee, date range, or to include voided payments.

**Expenses tab** — a list of all team expenditures. From this tab you can add, edit, and delete expense records (requires `finance:manage_fees`).

## Fee management page

Go to **Team → Finances → Fees** (`/teams/:teamId/finances/fees`) to create, edit, and archive fees and to assign fees to members. This page requires the `finance:manage_fees` permission (Admin or Treasurer by default).

From this page you can:
- Create a new fee (name, amount, currency, due date, scope).
- Assign an existing fee to individual members, with optional per-member amount or due-date overrides.
- Edit a fee's details or archive it when it is no longer needed.
- Waive an individual assignment (e.g. hardship exemption).
- Record a payment directly from the assignment list.

## Connecting a bank account (Fio)

If your club banks with **Fio banka**, Sideline can read your account's incoming payments automatically, match them to outstanding fees, and generate scannable payment QR codes for members — no more reconciling a bank statement against a spreadsheet by hand.

<Aside type="note" title="Fio only, for now">
  Automatic bank matching currently supports **Fio banka** accounts only. If your club banks elsewhere, you can still use everything else in this guide — fees, assignments, cash payments, expenses — you just won't get automatic matching or QR codes.
</Aside>

### Generating a read-only API token

<Steps>

1. Sign in to Fio Internetbanking at [ib.fio.cz](https://ib.fio.cz).
2. Open **Settings → API**.
3. Click **Create new token**.
4. Choose the **"Sledování účtu"** ("Account monitoring") permission.
5. Pick the club account and confirm.
6. The token is shown only once — copy it immediately.

</Steps>

<Aside type="caution" title="Never choose the order-submitting permission">
  Fio also offers a token permission that can submit payment orders. **Do not use it here.** The token is stored so Sideline can see incoming payments — with the read-only "Account monitoring" permission, even a leaked token cannot move a single crown out of the account. With the order-submitting permission, it could.
</Aside>

### Connecting the account

<Steps>

1. Go to **Team → Settings** and open the bank connection card.
2. Enter the account prefix (if any) and account number. Fio's bank code (`2010`) is filled in automatically.
3. Enter the club's recipient name — this is printed on payment QR codes and on the grant-export PDF.
4. Paste the API token you generated above.
5. Turn the connection **on** and save.

</Steps>

Optionally, expand **Details for documents** to add the club's IČO and registered address. These print on the PDF export's header for a municipal grant audit — the export still works without them, but a document for an authority should carry the club's identification.

<Aside type="tip" title="Give it five minutes">
  A freshly created Fio token needs about five minutes before Fio itself will accept requests with it. Sideline retries on its own during this window — you don't need to do anything, but don't be alarmed if the connection briefly shows "activating" right after you save.
</Aside>

Once connected, Sideline checks the account for new payments automatically, roughly once an hour.

### Testing the connection

Click **Test the connection** on the bank connection card at any time to check the saved token against Fio directly, instead of waiting for the next automatic check. The result tells you exactly what happened:

- **Fio accepted the token** — the token itself is good. Note that this checks the token only; the connection status shown above the button reflects the automatic hourly import, which is a separate, longer-running check and can still show a problem even right after a successful test.
- **The token belongs to a different account** — Fio accepted the token, but the account it reads doesn't match the account prefix/number saved on this card. Sideline stops importing rather than pull in someone else's payments, so this isn't cosmetic: the hourly import stays halted until you fix it. The result shows both IBANs side by side so you can see which is which. Fio doesn't send the account **prefix** back in its answer, so the most common cause is a missing prefix on this card — double-check it before assuming the token itself is wrong.
- **Fio rejected the token** — it's expired, revoked, or was never valid. Generate a fresh one following the steps above; a **Replace token** shortcut is offered right there.
- **Too many requests** — Fio limits how often the same token can be checked. Wait about 30 seconds and try again.
- **The history is locked** or **couldn't reach Fio** — neither of these means the token is bad; try again in a moment.

<Aside type="note" title="Test what you just pasted, not what's saved">
  The test always checks the **saved** account and token. If you've changed the account fields or pasted a new token but haven't clicked **Save Changes** yet, save first — otherwise the button is disabled with a hint explaining why.
</Aside>

### Importing older movements

By default, Fio only shares movements from the last 90 days. If you need older history — for example, to backfill a grant's reporting period — Fio requires you to explicitly unlock it first:

<Steps>

1. In Fio Internetbanking, open **Settings → API** and click the padlock icon next to your token.
2. This opens a **10-minute window** during which Fio will release older history.
3. Within those 10 minutes, go back to Sideline's bank connection card and start the import, choosing the date range you need.

</Steps>

If the window closes before you start the import, Sideline tells you the history wasn't released and lets you try again.

### If your token expires

Fio tokens last **at most 180 days**, and only renew themselves when someone actually signs in to Fio Internetbanking or Smartbanking. If nobody signs in for a long stretch, the token quietly stops working — and until someone notices, new payments stop being imported.

To make sure that doesn't happen quietly, Sideline warns you twice, starting two weeks out:

- **On the bank connection card**, a banner appears 14 days before your token's expiry and stays until you act.
- **By Discord DM**, sent to whoever configured the connection, at 14 days, 7 days, and 1 day before expiry.

Either way, you have two options: sign in to Fio Internetbanking or Smartbanking yourself (which renews the token with no action needed in Sideline), or generate a fresh token and paste it in following the steps above.

## Setting up variable symbols

A **variable symbol** is a short number (1–10 digits) that identifies who a bank payment belongs to — it's the standard way Czech and Slovak bank transfers carry this information, since the payer's name alone isn't reliable enough to match automatically. Sideline matches incoming Fio payments to a member's outstanding fees by this number, so **until a member has a variable symbol, none of their bank payments can be matched automatically** — this is the first thing to set up after connecting the account.

### Assigning symbols in bulk

The fastest way to get every existing member set up:

<Steps>

1. Go to **Team → Members**. If any active members are missing a variable symbol, a banner tells you how many.
2. Click **Assign symbols automatically**.
3. Sideline proposes a symbol for every member who doesn't have one yet — nobody who already has a symbol is touched. Review the list.
4. Confirm to save all of them at once.

</Steps>

### Setting or changing one member's symbol

Open the member's profile and edit the **Variable symbol** field directly, the same way you'd edit their jersey number. Symbols must be unique within the team — Sideline tells you which teammate already holds a symbol if you try to reuse one (leading zeros don't matter: `007` and `7` are treated as the same number).

<Aside type="tip" title="Who can do this">
  Assigning variable symbols only requires the ability to edit a member's profile (`member:edit`), which Captains hold by default — you don't need finance permissions just to give a teammate a variable symbol.
</Aside>

## The bank movements matching queue

Go to **Team → Finances → Bank movements** (`/teams/:teamId/finances/bank`, requires `finance:record_payments`) to see every payment Sideline has read from the connected account and, for anything that couldn't be matched automatically, resolve it by hand.

The page has three tabs:

**To match** — the queue of payments that need attention. Each row shows why it landed here: no variable symbol at all, a variable symbol nobody on the team holds, several members sharing the same symbol, an amount lower or higher than the fee, the amount matching more than one open fee, no open fee to match against, or a currency mismatch. For each one, you can:
- **Assign it** to a specific member's fee (or split it across several fees, if the amount covers more than one).
- Mark it as **other club income** — a genuine payment that just isn't a membership fee (a sponsorship, a donation).
- Mark it as **not relevant** — for example, a duplicate of a payment you've already matched (Sideline flags likely duplicates for you).

**Matched** — everything that's been resolved, whether automatically or by hand, plus anything marked as other income or ignored. Filter by how it was resolved. Each row shows exactly which member, fee, and amount it was matched to, and when.

**Grant export** — see [Exporting bank movements](#exporting-bank-movements-for-a-grant-audit) below.

<Aside type="tip" title="Undoing a match">
  If a payment was matched to the wrong member or fee, open it and cancel the assignment with a reason. The fee goes back to unpaid and the payment returns to the queue — nothing is deleted; the cancelled match stays in the history for the audit trail.
</Aside>

## Payment QR codes

Once a member has a variable symbol and the club's bank account is connected, Sideline can generate a scannable **SPAYD payment QR code** for any outstanding fee — the same format Czech banking apps already recognise, pre-filled with the club's account, the amount owed, the member's variable symbol, and a payment message.

**In Discord**, the payment reminder DM (see [Payment reminders](#payment-reminders) below) includes the QR code as an image attachment whenever one can be built, plus a plain-text fallback block for anyone who can't scan it.

**On the My Payments page**, click the QR icon next to any outstanding fee to reveal the code inline.

<Aside type="note" title="Why the QR text looks different from the rest of the message">
  The text encoded *inside* the QR code (the payment message and the recipient name) is written in unaccented, uppercase letters — for example `PRISPEVEK PODZIM 2026 NOVAK` instead of "Příspěvek podzim 2026 Nováková". This is a requirement of the SPAYD payment-QR standard itself, not a Sideline bug or a translation error — the rest of the message around the QR code keeps full Czech diacritics as normal.
</Aside>

If a member has no variable symbol, or the club hasn't connected a bank account, Sideline simply skips the QR — the reminder still sends as a normal text message, and the affected member sees a note explaining who to contact (their treasurer) to get set up.

## Exporting bank movements for a grant audit

Go to the **Grant export** tab on the Bank movements page to download a record of the account's movements for a chosen period — useful evidence for a municipal grant report or for handing off to an accountant.

<Steps>

1. Choose a date range (or use the "last year" shortcut).
2. Optionally, add a document label — for example, a grant contract number — which is printed in the file's header.
3. Choose **CSV** or **PDF** and download.

</Steps>

<Aside type="caution" title="Use the PDF for anything official">
  The CSV is formatted for Czech Excel (semicolon-separated, comma decimals) so it opens correctly with a double-click — but **Excel silently drops leading zeros from variable symbols and account numbers** when it opens the file (`0123456789` becomes `123456789`). For a municipal grant audit or any other official use, **download the PDF instead** — its figures are exactly as recorded.

  If you specifically need the CSV data with the leading zeros intact, don't just double-click it: in Excel, use **Data → From Text/CSV**, and when the import wizard asks for each column's type, set the variable-symbol and account-number columns to **Text** before finishing the import.
</Aside>

If the selected period isn't fully covered by what Sideline has actually imported from the bank — for example, part of the range was never fetched, or Fio's own reported balances don't add up for some reason — the export tells you exactly which dates are missing before you download anything. You can narrow the range, import the missing period first, or export anyway with a visible warning stamped onto the document.

## Expense tracking

Use the **Expenses tab** on the Finances page (`/teams/:teamId/finances`) to record and manage team expenditures — pitch hire, equipment purchases, travel costs, tournament entry fees, and anything else the team spends money on.

Expense management requires the `finance:manage_fees` permission (Admin or Treasurer by default). Members with only `finance:view` (Captain) can see the balance summary but cannot create or modify expenses.

### Expense categories

Every expense must be assigned one of the following categories:

| Category | Typical use |
|---|---|
| **Fields** | Pitch or venue hire |
| **Equipment** | Kit, cones, balls, bibs, and other gear |
| **Travel** | Transport costs for away fixtures |
| **Tournaments** | Entry fees for competitions |
| **Other** | Anything that does not fit the above |

### Recording an expense

<Steps>

1. Navigate to **Team → Finances** and open the **Expenses tab**.
2. Click **Add expense**.
3. Fill in the category, amount, currency, date, and a short description (max 500 characters).
4. Click **Save**. The expense appears in the list and the balance summary updates immediately.

</Steps>

### Editing or deleting an expense

Click any expense row to open the edit form. You can update any field. To remove the record, click **Delete** inside the form.

<Aside type="caution" title="Deletions are permanent">
  Expenses are hard-deleted — they cannot be restored from the UI once removed. An audit record is always kept internally, but it is not accessible through the web app.
</Aside>

### Balance summary

The **Overview tab** on the Finances page shows three KPI tiles — **Income**, **Expenses**, and **Net** — aggregated per currency. Income is the total of all non-voided fee payments; Expenses is the total of all recorded expense amounts; Net is Income minus Expenses.

You can filter the summary to a specific date range using the `from` and `to` query parameters via the API (see the [API section below](#captainadmin-workflows-via-api)).

### Expense API (for automation)

Admins and Treasurers can also manage expenses via the REST API.

#### List expenses

```http
GET /api/teams/{teamId}/expenses
```

Optional query parameters: `category`, `from` (ISO 8601), `to` (ISO 8601).

#### Create an expense

```http
POST /api/teams/{teamId}/expenses
Content-Type: application/json

{
  "amountMinor": 15000,
  "currency": "CZK",
  "spentAt": "2026-05-10T00:00:00.000Z",
  "category": "fields",
  "description": "Pitch hire — spring season round 4"
}
```

`amountMinor` must be a positive integer (minor currency units). The request returns `201 Created` with the full `ExpenseView` on success.

#### Update an expense

```http
PATCH /api/teams/{teamId}/expenses/{expenseId}
Content-Type: application/json

{
  "description": "Pitch hire — spring season round 4 (corrected)"
}
```

All fields are optional. If you supply `currency` you must also supply `amountMinor`.

#### Delete an expense

```http
DELETE /api/teams/{teamId}/expenses/{expenseId}
```

Returns `204 No Content` on success.

#### Balance summary

```http
GET /api/teams/{teamId}/finances/balance-summary?from=2026-01-01T00:00:00.000Z&to=2026-12-31T23:59:59.000Z
```

Returns `BalanceSummary[]` — one element per currency — with `incomeMinor`, `expensesMinor`, and `netMinor` fields.

## My Payments page

Any team member can visit **Team → My Payments** (`/teams/:teamId/my-payments`) to see a personal summary of all their fee assignments. No special permission is required — every member sees only their own data.

### Four KPI cards

| Card | What it shows |
|---|---|
| **Outstanding** | Total amount still owed (one entry per currency; additional currencies shown as "+N more") |
| **Overdue** | Count of assignments past their due date with unpaid balance |
| **Paid total** | Sum of all payments made (per currency) |
| **Next due** | Amount and due date of the earliest upcoming pending or partial assignment |

### Filter chips

Below the KPI cards a row of chips lets you narrow the assignment list:

- **All** — every assignment
- **Outstanding** — pending, partial, or overdue assignments
- **Paid** — fully paid assignments
- **Waived** — assignments the captain has waived

### Per-fee table

Assignments are grouped by currency. Each group is displayed as a table with columns for **Fee name**, **Due date**, **Amount paid**, and **Status badge**. Click the chevron on any row that has recorded payments to expand an inline payment history showing the amount, method, date, and who recorded each payment. On any outstanding fee, click the QR icon to reveal a scannable [payment QR code](#payment-qr-codes) for the remaining balance, if the club has connected a bank account.

### Outstanding / overdue alert banner

When a member has outstanding or overdue fees, a banner appears at the top of the **Team Dashboard** page with a summary of the amounts owed and a direct link to the My Payments page.

## Checking your own balance in Discord

Any member can check their own fee status using the `/finance status` slash command.

<Steps>

1. Open Discord in any channel where the Sideline bot has permission.
2. Type `/finance status` and press Enter.
3. The bot replies with an ephemeral (visible only to you) embed.

</Steps>

The embed colour tells you at a glance where you stand:

- **Green** — all fees paid or waived.
- **Amber** — one or more fees are pending or partially paid.
- **Red** — one or more fees are overdue.

Each outstanding fee appears as a field showing the fee name, amount still owed, and due date. Overdue items also show how many days past due they are.

<Aside type="caution" title="No access? Check with your captain">
  If `/finance status` tells you "not a member", your captain needs to make sure your Sideline profile is linked to your Discord account. If you have no fees assigned at all, the bot shows the green all-clear embed.
</Aside>

## Payment reminders

Sideline automatically sends you a Discord DM when a fee is assigned to you and again at each of five reminder points relative to its due date:

| When | Reminder |
|---|---|
| As soon as a fee is assigned to you | A neutral "you've been assigned a new fee" message (blue embed) |
| 3 days before due | "Heads up — payment due soon" (blue embed) |
| On the due date | "Payment due today" (yellow embed) |
| 3 days overdue | "Payment overdue" (red embed) |
| 10 days overdue | "Payment overdue" (red embed) |
| 21 days overdue | "Payment overdue" (red embed) |

Each DM shows the fee name, total amount, how much is still outstanding, and the due date. If your club has a connected bank account and you have a variable symbol, the DM also includes your [payment QR code](#payment-qr-codes) and a "Moje platby" button linking straight to your My Payments page. Reminders stop automatically once the assignment is marked paid or waived.

<Aside type="note" title="Reminders require Discord DMs">
Reminders are sent as Discord direct messages. If you have DMs from server members disabled in your Discord privacy settings, you will not receive them. Check **User Settings → Privacy & Safety → Allow direct messages from server members** if you are not getting reminders you expect.
</Aside>

### Payment due dates in your calendar

Your personal iCal feed (see [Calendar subscription](/guides/calendar-subscription/)) also includes an all-day event for each unpaid or overdue fee assignment, with a built-in alarm that fires one day before the due date. This gives you a second reminder channel alongside the Discord DMs, and lets you see upcoming payment deadlines alongside team events.

## Captain / admin fee workflows (via API)

Most fee management tasks are available through the web UI (see the [Fee management page](#fee-management-page) section above). For scripted or bulk operations, admins and treasurers can also use the REST API directly. See the [API overview](/api/overview/) for authentication instructions. For expense API examples see the [Expense API](#expense-api-for-automation) section above.

### Create a fee

```http
POST /api/teams/{teamId}/fees
Content-Type: application/json

{
  "name": "Spring 2026 membership",
  "amountMinor": 50000,
  "currency": "CZK",
  "dueAt": "2026-03-31T23:59:59.000Z",
  "targetScope": "all_members",
  "description": null
}
```

`amountMinor` is the amount in the smallest unit of the currency (e.g. hellers for CZK, cents for EUR). 50 000 hellers = 500 CZK.

### Assign a fee to members

```http
POST /api/teams/{teamId}/fees/{feeId}/assignments
Content-Type: application/json

{
  "memberIds": ["member-uuid-1", "member-uuid-2"],
  "amountMinorOverride": null,
  "dueAtOverride": null
}
```

Pass `amountMinorOverride` or `dueAtOverride` to override the fee's defaults for specific members. Pass `null` to use the fee-level values.

### Record a payment

```http
POST /api/teams/{teamId}/fees/{feeId}/assignments/{assignmentId}/payments
Content-Type: application/json

{
  "amountMinor": 50000,
  "method": "cash",
  "paidAt": "2026-02-15T10:30:00.000Z",
  "note": "Paid at training"
}
```

`method` is either `"cash"` or `"bank_transfer"`.

### Void a payment

```http
DELETE /api/teams/{teamId}/payments/{paymentId}
Content-Type: application/json

{
  "reason": "Entered against wrong member"
}
```

The payment is marked voided (not deleted). The assignment's paid amount is automatically recalculated.

### Waive an assignment

```http
PATCH /api/teams/{teamId}/fees/{feeId}/assignments/{assignmentId}
Content-Type: application/json

{
  "waived": true,
  "waivedReason": "Hardship exemption approved by committee"
}
```

### Archive a fee

Archiving a fee hides it from active listings but preserves all assignments and payments for historical records.

```http
DELETE /api/teams/{teamId}/fees/{feeId}
```

Archived fees cannot be modified. Create a new fee if you need to issue a revised charge.
